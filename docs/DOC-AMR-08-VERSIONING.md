# DOC-AMR-08: 版本线（1.x / 2.x）与兼容性

日期：2026-11-15
状态：2.x 开发中；1.x 为当前生产基线。

## 为什么既有 v5 标签又有 1.x / 2.x

仓库历史标签 `v5.0.0`、`v5.0.1`、`v5.1.0-complete-consolidation` 描述的是
**存储/协议/可靠性版本**（SQLite SSOT、Qdrant 投影、UDS 协议等）。本次引入的
**接入架构版本**单独编号：

| 版本线 | 含义 | 接入方式 |
| --- | --- | --- |
| **1.x** | 当前生产基线 | 本地 UDS 直连 + MCP stdio 桥接；无网络暴露 |
| **2.x** | 本次开发线 | 认证 HTTPS MCP + 本地 UDS 适配器 + 2.x 客户端插件 |

两者不是同一维度，因此不删除或重写历史 `v5.x` 标签，避免破坏已有发布记录。

## 基线对应关系

- **1.x 基线提交**：`e4d8677`（`v5.1.0-complete-consolidation`，`main` 当前指向）。
- **1.x 分支**：`release/1.x`（指向同一提交，只接受 1.x 修复）。
- **2.x 分支**：`release/2.x`，从 1.x 基线拉出；`VERSION` 为 `2.0.0-dev.1`。
- **数据兼容**：2.x 保留现有 SQLite 业务表 / Qdrant 集合 / `memory.*` 工具语义，
  并新增 `message_source_revisions` 辅助表用于可选快照水位保护；这是增量 schema
  变化，不是“schema 完全不变”。旧版 daemon 不执行水位检查，若回滚后修改受保护
  消息，新版再次摄取时会检测哈希基线冲突，需要人工核对。1.x 数据可在备份后由
  2.x 打开；回滚须按备份流程演练。**任何时刻只允许一个写者**，禁止 1.x
  与 2.x 同时写同一数据目录。

## 版本号规则

- AMR 2.x 的版本以仓库根目录 `VERSION` 为准（当前 `2.0.0-dev.1`）。
- 各客户端插件包版本从 `2.0.0` 起（1.x 插件为 `1.0.0`），包名保持不变。
- `v2.0.0` 正式标签只在以下条件全部满足后创建：
  1. HTTPS MCP 服务、UDS 适配器、各 agent 2.x 插件的隔离测试全绿；
  2. Gemini 与 DeepSeek 交叉审计无未关闭的高/中风险项；
  3. 1.x 生产未被改动，且迁移/回滚演练文档完成。
- 开发期标签使用 `v2.0.0-dev.N`，不推送到公开远端，除非明确要求。

## 分支纪律

- `main` 保持 1.x 生产可发布状态；2.x 开发在 `release/2.x`。
- 2.x 的提交不得修改 1.x 的运行路径（`src/main.py`、生产 `config/config.yaml`、
  `amr.service`），除非同时提供 1.x 不受影响的证据。
- 合并回 `main` 之前必须完成迁移与回滚演练；在此之前 `main` 不接收 2.x 代码。
