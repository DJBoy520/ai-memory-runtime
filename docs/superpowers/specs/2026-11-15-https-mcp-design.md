# AMR 认证 HTTPS MCP 设计草案

## 目标和范围

Ubuntu VM 中的 Claude、Codex、OpenClaw、OpenCode、DSH 等继续使用 AMR；AMR 将来运行在 Unraid Docker 并使用 Tesla P4。新增标准 Streamable HTTP MCP 接口，经 HTTPS 加密并认证。旧本地 stdio/UDS 接入继续可用。先在隔离环境验证，不修改生产服务、Unraid、真实数据或 GPU 直通。

AMR 面向同一个人的多个 Agent 共享记忆，所有接入的 Agent 属于同一个信任域。项目 ID 用于数据筛选和组织，不是权限隔离边界；本方案不要求不同 Agent 或项目之间隔离记忆。网络认证和加密用于限制未授权设备访问并保护传输，身份记录用于区分来源。

## 已选择的方向与备选

已选择认证 HTTPS MCP：支持远程 MCP 客户端直接连接。SSH socket 转发可以复用原始协议，但需要维护 SSH 账户和隧道；逐个重写所有原生插件则扩大切换范围。为兼容直接使用 UDS 的插件，在 Ubuntu 提供受限的本地 UDS 到远程 MCP 适配器，逐个验证原有自动 hook。

## 组件和安全边界

- Unraid 容器运行 AMR 与 MCP HTTP 端点；MCP 端点仅转发业务工具，管理 socket 不通过网络暴露。现有工具定义与参数校验保持一致，拒绝无对应工具的 RPC。
- HTTPS 由明确配置的 TLS 终止层提供；不允许默认对外暴露明文端点。客户端必须验证证书与主机名，支持配置自有 CA，不提供跳过验证的生产选项。实现及部署文档须说明代理至后端的信任边界，后端仅监听 loopback、Unix socket 或严格隔离的容器私网，并验证客户端不能绕过代理直接访问；私网本身不构成客户端认证。
- 每个客户端使用独立高熵凭证；服务端验证凭证并将其绑定到固定 agent 身份，忽略或拒绝与身份冲突的用户参数，不能把 `agent_id` 白名单当网络认证。凭证不写入仓库、日志或 URL；支持轮换/吊销，默认拒绝匿名访问。按最小权限区分业务工具，危险管理操作不提供远程接口。
- 对每个工具调用按凭证的工具允许列表检查授权并记录不含正文的审计事件；默认拒绝未列出的工具。同一信任域内的 Agent 可以共享记忆，不按项目或 Agent 限制数据可见性。
- 遵循实际选定并锁定的 MCP SDK 与协议版本，验证初始化、工具发现、调用、错误、通知与并发；进行 Origin 校验、请求体/连接限制及超时控制。清晰标记认证错误、传输错误和应用错误。

## 客户端兼容与可靠性

- 支持远程 MCP 的客户端可直接访问 HTTPS 服务，但直接连接不能提供 Ubuntu 侧离线队列；需要可靠离线归档的客户端必须使用本地适配器或自有持久队列。尚不支持远程 MCP 者可使用 Ubuntu 的 stdio 适配器。
- 现有 OpenClaw/OpenCode/DSH 插件使用的本地 UDS 协议，由 Ubuntu 上的适配器映射到 MCP 工具；保留 RPC 参数、响应与错误语义，验证每个插件实际调用的方法。适配器仅监听用户受限的 socket，不能将 admin 方法透出。每个固定身份使用独立 socket 和凭证；逐项列出插件使用的 RPC、工具映射及请求响应形状，未知方法拒绝，不能让任意请求伪造来源。
- 会话摄入和检查点仍在 Ubuntu 持久排队，重启与网络恢复后重试；记录 `queued` 与服务端确认的区别。稳定的消息 ID 和幂等键用于超时后安全重试；不能叠加两个相互独立重放的队列。对其他写操作明确返回失败或状态未知，不声称自动排队。认证拒绝与证书错误必须区分暂时性断网，隔离并报告，不无限自动重试。
- 离线队列须配置容量与磁盘余量上限；空间不足时显式失败，不丢弃已排队数据或报告排队成功。沿用并验证服务端 `(session_id, message_id)` 去重与检查点幂等键，明确其持久化、冲突和保留期限，不能仅依赖客户端去重。
- 保持 OpenClaw 等 hook 的 fail-open 和可配置超时；为认证失败、证书失败、不可达、超时、排队和重试提供不泄露内容的可观测信息。实际网络期限根据测试配置，不承诺现有 80ms 能适用。

## 部署、迁移和回滚

提供可复现的镜像/配置、TLS 与凭证样例、Unraid 部署文档和健康检查。SQLite/WAL 和模型需要持久化，Qdrant 连接与密钥独立配置；蒸馏和对账调度明确迁移，不把 dry-run 描述为修复或备份。固定 GPU 运行时依赖并在目标验证 P4、CUDA、显存和设备实际使用。新旧实例不得并行写同一数据；先备份并验证恢复，停旧写者、复制一致数据、验证索引及客户端，再切换；失败时停新写者并按演练过的数据库及二进制备份恢复旧实例；记录切换后写入并明确恢复旧备份可能丢失这些写入，不声称无损回滚。版本化 schema 迁移，验证新旧版本兼容及恢复路径，保留可复现旧镜像。目标机尚未实测，任何切换均另行安排。

证书计划：使用 AEP-PKI 为最终访问域名签发服务端证书，优先评估 ECDSA P-256，以兼容现有 Python/OpenSSL 客户端；AEP-PKI 文档提示 SM2 链在常见 OpenSSL 验证路径存在兼容性限制，不能未经验证用于默认部署。证书 SAN 必须匹配客户端实际使用的 DNS 名称，若使用 IP 则必须包含对应 IP SAN，具体签发支持需在目标 CA 实测。服务端安全挂载证书链与私钥；Ubuntu 适配器配置受信 CA，严格校验证书链及主机名。部署前核实 CA 链、域名解析、证书续期与服务热重载，轮换 CA 时支持受控信任重叠；未经用户部署安排不签发证书、不更改 CA 或系统信任库。AEP-PKI 的 ACME 使用文档提供 DNS-01/HTTP-01 与续期示例，但目标环境配置及可用性仍需核验。

## 验收

1. 在隔离数据库和模拟后端上，标准 MCP 客户端通过 HTTPS 完成发现、查询、写入、取回和错误处理；证书无效、缺失/错误凭证、身份伪造及管理方法均被拒绝。
2. UDS 原生插件模拟调用经适配器成功映射；断网归档排队，进程重启后恢复，服务端已提交但响应丢失的重试不产生重复，且 `queued` 不冒充已提交。
3. 多客户端并发、超时、服务重启和客户端取消得到可解释结果；日志不包含密钥或会话正文。测试只使用隔离目录、socket 和数据，禁止触达生产。
4. 现有 stdio/UDS 模式回归；OpenClaw 真实 hook 授权与迁移后的实际检索/归档分别验证。
5. 在目标 Unraid 上独立完成 TLS、P4、持久化、定时任务、备份恢复、切换和回滚演练后，才判断可否迁移。
