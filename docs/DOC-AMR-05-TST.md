# AI Memory Runtime - 测试与验证基线 (TST)

**文档标识**：`DOC-AMR-05-TST`  
**版本号**：`v2.2.0`  
**测试范围**：单元测试、集成测试与基础协议校验

---

## 1. 测试策略

项目测试重点覆盖以下维度：
1. **协议与通信**：UDS 4 字节长度前缀解析、JSON-RPC 契约与 4MB 单包防护；
2. **状态流转与数据一致性**：会话消息的幂等写入、内容哈希防重、以及记忆状态过滤；
3. **向量同步与发件箱**：Outbox 异步消费、重试逻辑与 Qdrant 点位状态更新。

---

## 2. 核心测试用例

| 用例编号 | 涉及模块 | 测试场景与操作 | 验证标准 |
| :--- | :--- | :--- | :--- |
| **TC-PROTO-01** | IPC 协议 | 发送标准 JSON-RPC 2.0 请求包 | 正常解析 4 字节长度头并返回对应响应 |
| **TC-PROTO-02** | IPC 协议 | 发送超 4MB 异常数据包 | 服务端直接断开连接，避免资源消耗 |
| **TC-MEM-01** | 记忆检索 | 执行 `memory.search` | 仅返回处于活跃状态的记忆，按相关度排序 |
| **TC-MEM-02** | 状态更新 | 执行 `memory.update` 修改状态 | 状态正确变更为已归档，后续检索被过滤 |
| **TC-SES-01** | 会话持久化 | 连续两次摄取相同会话消息 | 第二次自动忽略，数据库条目不重复增加 |
| **TC-SES-02** | 会话更新 | 摄取相同 ID 但内容变动的消息 | 识别到哈希变动并更新内容，更新计数加一 |
| **TC-OUTBOX-01**| 向量同步 | 写入新记忆卡片 | 本地表新增记录，同时发件箱生成待处理任务 |
